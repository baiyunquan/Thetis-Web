# UI behavior baseline

The [machine-readable ledger](D:/workspace/Thetis/ui/baseline/ledger.json) assigns all 161 candidates in the [source inventory](D:/workspace/Thetis/docs/superpowers/specs/2026-11-08-code-oss-ui-source-inventory.md): 56 Form class names, 16 UserControl class names and 89 Setup TabPage constructions. This is discovery coverage and explicit stage ownership. It does not establish complete interaction parity or runtime reachability.

The [validator](D:/workspace/Thetis/ui/baseline/validate.mjs) reparses the source inventory independently of ledger IDs and counts. It checks exact candidate membership, duplicates, ownership, target IDs, original source declarations, actual source symbols/lines, existing evidence files, historical authority and unqualified measurement fields. Changing a ledger count cannot conceal a missing candidate. [Vitest regressions](D:/workspace/Thetis/ui/tests/foundation/baseline.test.ts) include intentionally unassigned/missing/duplicate rows and a historical screenshot overriding a current handler. The dependency-free [Node regressions](D:/workspace/Thetis/ui/baseline/validate.node.test.mjs) exercise the same contract.

Each discovery row retains its original `inventoryStep` text. `ownerStage` identifies one accountable stage; it is not an exclusion of later work. Cross-cutting helpers belong to Stage02 unless specifically triaged into Stage01. Console and Setup each have one primary owner and retain their split-stage inventory annotation. Targets are planned workbench identities; assigning an identity does not claim that its editor has been implemented. Setup target suffixes preserve the actual page variable so duplicate human labels cannot collapse distinct pages.

`sourceRefs` contains the source declaration/construction from the inventory. `handlerRefs` contains representative current event-handler declarations found from static hookups, up to four per discovery candidate. A Setup page's handlers are selected from that page's static descendant control tree. These lists are explicitly incomplete; `behaviorExpansion` remains pending for per-action validation, keyboard/mouse context actions, Apply/Cancel, persistence, restart and external control. A candidate with no resolved static handler keeps an empty list rather than inventing a method. The 29 detailed Console records add current handlers, initial states, actions, expected results, units, validation, persistence, external mapping and qualification needs.

The [generator](D:/workspace/Thetis/ui/baseline/generate-ledger.py) preserves reproducible discovery and explicit, reviewed Console mappings. Run it only after reviewing source/manual changes; review its JSON diff before accepting new evidence. No production runtime component imports this ledger or executes its legacy handler names remotely.

```powershell
python ui/baseline/generate-ledger.py
node --test ui/baseline/validate.node.test.mjs
node ui/scripts/test.mjs unit tests/foundation/baseline.test.ts
```
